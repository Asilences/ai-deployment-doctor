# 失败反馈后的提案约束：规划器 v2 诊断

v1 探索性试点见 [结果](PILOT_RESULTS_2026-09-24.md)。低并发任务中，模型在第一次 `(4,512)` 被拒后仍原样重复该候选，浪费一次真实性能测量。v2 把当前配置和历史已测配置列为禁选；若本地模型首次输出无效或重复配置，最多请求一次纠错，仍不合格就拒绝执行。控制器不代替模型选择配置。此版 `planner.py` 文件 SHA-256：`620097DB3FB7AD3ECE5E708960E778D9678E2C33A2A590AFB18A07F98A16E57A`。

在相同低并发任务上单独运行 v2，预算仍为两项提案。第一轮模型提出 `(4,256)`，相对参考约 -0.26%，拒绝。第二轮提案不合格，返回 `proposal_failed`，没有执行候选。最终保留原始 `(2,128)`；[独立复测](../runs/llama_cpp-final-20260924-130723-675f72/final.json)有效，定义的相对收益为 0%。[完整运行记录](../runs/llama_cpp-local-20260924-130505-4a98c7/run.json)可核对两轮决策。

这证明“重复候选不再重复压测”的安全属性，**不证明规划能力改善**。小模型仍可能在一次纠错后无法输出可执行新候选。更稳健的下一版可以让模型从控制器提供的、已排除访问历史的候选编号列表中选择，而不是自由生成两个参数；这种映射仍应由模型选择编号，控制器只验证和执行。需先单独测试该机制，不能把 v2 与 v1 试点混算为同一方法。
