## 已核对与结论边界

- 逐调用重算账本，与 run 的调用数、token、未知量及时间一致；候选目录、baseline 排除与实际映射正确。
- 从实际请求 evidence 核对字段消融：full 包含五类证据；no_feedback 无当前指标 / 历史；no_context 无环境 / 硬件 / 负载。共同可用列表、当前配置和约束仍存在。
- 独立 final 的 source run、best 文件 SHA-256、配置、设置与原始运行一致；精确请求数、输入输出长度及功能检查通过。原 `core.py`、后端、audit、final 逻辑与基线提交一致；控制器变更形成新指纹。
- 信息改变了本次选择，但完整信息版本没有收益，去掉环境与负载字段反而找到一项收益。不能据此声称上下文必然有害，也不能把不同提示长度、单次模型选择和时间位置的影响单独归于某个字段。
- full 与 no_context 解释仍把未测配置说成“最高吞吐”；格式有效并不等于根因诊断可信。外部 verifier 阻止了 full 的错误性能判断被保留。
- 每项只有一个槽位，不存在候选历史反馈。因此本批次不能证明从失败中学习、L4 或 L5；本机闭环证据与策略优势必须分开。

固定规则来自先前开发任务，不是无信息基线；它作为强对照提醒我们，已有收益可能只是常见配置选择。随机只完成两个种子，不能给完整三种子均值；未完成批次也不用于显著性检验。
