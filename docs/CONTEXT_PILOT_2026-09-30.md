# 信息消融开发试点：执行前冻结协议

本协议在实测前保存，延续原 2026-09-24 试点；已有开发负载不改称 holdout。目的为验证比较工具和定位失败，不用于证明 Agent 普遍优于随机搜索。

## 比较对象与公平性

- `local:full`：本地 v3.1，完整环境、硬件、负载、当前指标及历史反馈。
- `local:no_context`：删除环境、硬件、负载字段，保留当前指标及反馈。
- `local:no_feedback`：删除当前指标与历史反馈，保留环境、硬件及负载。
- `random`：均匀无放回配置搜索，显式种子 100、101、102，全部分别报告。
- `fixed`：此前开发数据选定的 `(parallel=4, ubatch_size=512)`，强固定规则基线；不能视为完全没有开发信息的对照。

控制相同模型及文件哈希、起点 `(2,128)`、16 项配置空间、任务请求、独立 final 和验收器。三个本地方法使用同一个候选 ID 接口、长度约束、固定单槽规划服务和每提案最多两次调用。随机和固定方法无需模型推理；同槽位上限不等于同成本，另列实际候选数、模型调用、token、规划启动及耗时。

信息消融只删除明确字段。当前指标仅提供吞吐与两项延迟，不提供请求长度或请求数；性能仍可能间接透露负载 / 硬件信息。所有方法都保留共同目标、延迟限制、当前配置及可用候选；后两项会间接透露尝试历史。`no_feedback` 是移除语义测量反馈，不是消除一切历史信息。

独立环境和负载消融 `no_environment`、`no_workload` 已提供接口与受控测试，本批次不运行。一次提案时没有历史候选结果，因此 `no_feedback` 本次只检验去掉 baseline 指标的影响，不能检验从失败中学习。

## 首批执行计划

只运行已有长输入高并发开发任务：24 请求，384 输入 / 32 输出 token，并发 8。各方法 / 种子从同一起点独立运行，无跨运行继承；每项最多 **一个提案槽位**。种子 20260930 在运行前随机化顺序，固定为：full、random 101、random 102、no_feedback、no_context、fixed、random 100。每项搜索结束后独立 final，不把搜索阶段最高吞吐用作最终分数。

```powershell
python -B scripts/run_context_pilot.py --tasks prefill --methods full no_context no_feedback random fixed --iterations 1 --random-seeds 100 101 102 --order-seed 20260930 --max-seconds 900
```

整个调用 900 秒软上限；达到时限不开始下一项搜索或 final，允许正在执行的验证 / 恢复安全结束。未完成任务保留 pending 或 final pending，不能算作零收益或成功。`--resume <批次目录>` 在源码和配置哈希不变时继续尚未开始的任务；中断的搜索不自动重做，已经完成的运行不覆盖。

`--dry-run` 只查看计划，不启动服务或新建批次。源码和配置身份在 manifest 保存；每次请求记录实际提供的 evidence，用于核对消融，没有借助解释文本推断模型看到了什么。

## 指标、证伪与解释边界

报告合法 / 重复 / 无效提案率、每种子的 ID 与配置、接受 / 恢复、独立 final 的有效性及收益、全部已知成本及未知量。按任务配对 full 与每个对照；多个随机种子不是多个任务，不挑最优或最差种子。比较要求同任务、硬件和 evaluator 源码身份；不存在唯一 full 或有效 final 时不选分数。

可能被证伪的诊断假设：显式信息使模型选择不同、且经独立验证更好的配置。相同候选 / 分数、无效提案、无收益、或简单对照同样好，均不支持该假设。即使本批次 full 更好，单一已用开发任务、每方法一次模型调用仍不足以估计成功概率、显著性或泛化；下一步需多任务、多个独立分块、相同冻结协议。

固定 verifier 保持三次交替测量、5% 提升及区间分离、精确请求与 token 完成、功能冒烟测试、重启复核及恢复规则。代码变更产生新指纹；旧运行不能跨指纹继承或重新评分。

测试：52 项通过，包括实际请求字段消融、旧接口约束、计划种子 / 唯一任务与固定规则预算、配对不把种子当任务及不择优 final。实测后将原始结果入口追加到工作日志；`runs/` 仅本地保存，不上传公开仓库。
