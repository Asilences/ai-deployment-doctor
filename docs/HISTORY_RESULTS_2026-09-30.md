# 两槽位历史反馈：实测、证据错误与下一步

执行前 [协议](HISTORY_PROTOCOL_2026-09-30.md)，实验源码提交 `fc94dcf587e890aa9b228c161796a0bed796a4e2`，两项 Git dirty 均为 false。一个已用 prefill 开发任务，full / no_history 各两个槽位，独立起点、独立 final，固定 verifier。完整批次 **560.5 秒**，没有触发 900 秒软上限。

**本轮没有观察到历史反馈的性能收益。** full 两项均被拒，no_history 第二项通过、最终约 +6.98%；但首项选择不同，不能把最终差异单独归因于历史字段。

## 观察到的证据归属错误

no_history 第二轮的 expected_effect 为：

> The model achieves a higher output throughput of 149.6015106636072 tokens/s.

这个数字逐字来自 **当前 C05 的实测吞吐**，C08 提案时未测；它也没有高于所见的当前吞吐。该表述不能作为新候选已有效的证据。full 也继续使用未测配置“最高吞吐”的表述。实际验证依据是后续外部测量，不是这些解释。

目前已修复格式闭合、非法 / 重复执行和成本丢失；未解决测量归属、推理可靠性或策略优越性。成功的 C08 支持有限动作空间自主提案可产生真实收益，不能证明从历史反馈学习、更不能证明 L4 / L5。人工加入消融和审计也不是 Agent 自我改进。

## 下一步优先顺序

先做 **同一状态的提案重放**：固定一个真实失败后的 snapshot、精确指标、可选列表、模型和生成参数；full / no_history 仅历史字段不同，比较候选分布及错误归属。它能排除本轮轨迹差异，但只判断提案是否受信息影响，不能单独证明真实性能收益。重放不用于覆盖本轮结果或直接提升 best。

然后单独编号一种证据表示：把测量与配置 ID / config 明确绑定，把未测候选标成 unknown；用冻结 snapshot 比较与原表示的选择与引用正确性，避免同时更换模型而无法归因。若仍无法处理简单证据，再另立更强规划模型的对照；后端、模型权重优化目标与外部 verifier 保持固定。

只有这些诊断显示可信改进，再投入多任务、两槽位、随机多种子与 fixed 的完整等上限分块实验。当前不扩展 Memory、主动 Probe、L5，也不把反复调整已用任务提示得到的结果当作 holdout。
