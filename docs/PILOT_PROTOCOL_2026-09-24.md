# 环境感知优化试点协议（探索性）

本协议在并发 1 的固定规则筛查结果已知之后记录；因此以下试点用于检查程序与任务难度，**不作为预注册确认性实验**。之后的确认性任务须换用新模型或机器，并在运行方法前冻结。

## 冻结条件

- 机器：本机 RTX 3070 Ti Laptop GPU；llama.cpp b11138 Vulkan；Qwen2.5-1.5B-Instruct-GGUF Q4_K_M。
- 配置空间：`parallel ∈ {1,2,4,8}`，`ubatch_size ∈ {64,128,256,512}`；起点 `(2,128)`。
- 两种负载：`configs/pilot-serial-windows-1.5b.json`（16 请求，64/32 token，并发 1）；`configs/pilot-prefill-windows-1.5b.json`（24 请求，384/32 token，并发 8）。
- 主要比较预算：最多 2 个候选。Agent 使用本地模型、温度 0；随机搜索使用种子 100、101、102。固定 `(4,512)` 规则只提出一个候选，是无反馈参照，不假装使用第二个名额。
- 所有方法使用同一原始配置、相同评测器与验收门槛、各自独立运行。随机运行不继承 Agent 的状态。
- 搜索结束后用 `python -m inference_lab final --config <原任务配置> --candidate <该运行/best.json>` 重新交替测量原始和保留配置，各三次；主要结果是此次独立复测的吞吐比。负载、模型、源码指纹不一致则拒绝评分。功能或请求不完整时标记为无效，不把搜索内的最好数字当最终分数。
- 另外报告接受率、候选提案数、无效或重复提案、规划器 token 用量和运行时；不把单一任务的压测重复次数当作独立任务数。

## 判读

本机只有一种模型和一种硬件，两个负载也在开发期确定。即使 Agent 在这里超过随机搜索，也只能说明试点可行。若 Agent 在低并发环境仍机械地提出 `(4,512)`，而它没有通过固定规则筛查，则当前规划器缺乏有用的环境区分能力，需要先分析失败，再冻结新设计进入确认性实验。
