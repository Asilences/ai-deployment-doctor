# 规划器 v3：候选 ID 与提案成本账本

## 本轮假设与边界

假设：显式列出合法未试配置并让模型选择 ID，可以避免重复配置进入真实性能测量，且能让无效输出和纠错成本可核对。是否减少无效输出需要实测；不要求配置收益为正。

独立变量：v3 候选选择接口。控制条件：已有本地模型、16 项配置空间、原始起点、两项开发负载和现有 verifier。每个负载最多两次提案槽位，每槽位最多两次模型调用；纠错不是免费动作。结果仅用于开发验证，不与 v1/v2 结果合并，不用于确认性优越性声明。

判别结果：所有执行配置必须来自当前可选 ID；重复 / 无效输出不得执行；每次调用都进入账本，包括失败。若上述条件不成立，机制假设被工程证据否定。即使均成立，也不能证明 Agent 利用了环境证据。

## 接口与固定目录

`--planner local --planner-version v3` 开启；省略版本仍采用 v2。v3 暂不支持 OpenRouter 或其他规划器。候选目录先按参数名排序，再按数值升序生成笛卡尔积，使用 `C00` 至 `C15`；当前空间中 `C05=(2,128)`，`C11=(4,512)`。ID 不随候选删除而重新编号。

模型返回且仅返回 `candidate_id`、`hypothesis`、`expected_effect`。控制器校验 ID 并映射为配置，绝不代替模型选择 ID。当前配置及此前实际尝试执行的候选被排除；执行失败也消耗实验机会。无效输出最多一次纠错，之后记录失败。耗尽时无模型调用并结束搜索。

v3 提案阶段固定使用 `(parallel=1, ubatch_size=128)` 服务配置。因为现有 llama.cpp 将固定总上下文分给并行槽位，若直接在不同 incumbent 配置上规划，候选列表的可用上下文和调用条件会变化。单槽位服务仅承载提案，不参与候选性能得分；其启动成本单独记录。模型权重、总上下文、推理引擎及测量协议不变。本地请求温度 0、seed 42；这不保证跨硬件完全确定。

## 记录与成本解释

- `proposal_calls`：每次调用的时间、耗时、用量、解析结果、失败类别；v3 还记录可选目录与请求指纹。本地模型文本保留；远程响应正文、请求头及凭据不保存。
- `costs`：调用和纠错次数、已知 token 小计、用量缺失次数、总 token（任一调用缺失则未知）、提案耗时、规划服务启动耗时、实际候选实验次数、恢复次数与运行总耗时。
- `candidate_executed` 表示已开始尝试执行该候选；不保证测量完成。`rollback_count` 统计已核实的 incumbent 恢复，不把成功 promotion 算成 rollback。
- 提案失败进入完整历史；账本只包含本次运行成本，继承历史不重复计费。
- 全部代码哈希、Git commit / dirty 状态、规划器版本、硬件摘要及环境指纹进入运行记录。新记录格式为 `proposal-ledger-v1`；旧记录不会补造未知成本。
- `--max-seconds` 控制不再开始新提案槽位，允许当前验证和恢复结束，不强杀服务。

本轮没有修改性能判据。控制器源码发生变化，因此原有继承 / final 的源码指纹检查仍会拒绝跨版本直接比较；不能绕过检查去重评旧状态。

## 运行与只读汇总

在项目根目录执行：

```powershell
python -B -m unittest discover -s tests -v
python -B -m inference_lab run --config configs/pilot-serial-windows-1.5b.json --planner local --planner-version v3 --iterations 2 --max-seconds 900
python -B -m inference_lab final --config configs/pilot-serial-windows-1.5b.json --candidate <新运行目录>/best.json
python -B -m inference_lab summary --input runs --format json
python -B -m inference_lab summary --input runs --format csv --output <不存在的新汇总文件>.csv
```

`summary` 只读取原始记录；指定输出时只创建新文件，拒绝覆盖。最终收益必须来自独立 final，且原始状态文件哈希、负载和保留配置匹配；搜索内最高值不作为 final。多个匹配 final 标记歧义，不选最大或最新。JSON 未知为 `null`，CSV 为 `unknown`；旧日志的总调用成本无法可靠恢复。

原始 `runs/`、模型、vendor 和密钥只保存在本地，不随 GitHub 上传。历史文档中指向 `../runs/...` 的链接是本地证据入口，在公开仓库中不可访问。
