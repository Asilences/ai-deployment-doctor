# 已保存配置的留出负载审计：2026-09-24

## 目的与设计

首轮 Agent 在 16 个请求、128 输入 token、32 输出 token、并发 8 的负载下选择并验证了 `(parallel=4, ubatch_size=512)`。本审计冻结这个 `best.json`，只改变请求负载，在两组未参与选择的负载上与原始配置 `(2, 128)` 比较。审计程序会核对来源实验已完成、配置确曾被接受、评测器源码未变化，且模型、运行时和其他验收设置完全相同；不会写回来源实验或更新配置。

每组都在同一 RTX 3070 Ti Laptop GPU 上运行 Qwen2.5-1.5B-Instruct-GGUF Q4_K_M 与 llama.cpp b11138 Vulkan。两种配置交替重启、预热、测量，各三次。所有请求必须完整返回固定 token 数，三个固定功能 prompt 的输出必须一致；报告中的 `verified_gain` 仍采用 5% 增益和三次测量区间分离门槛，仅表示该组工程验收通过。

## 解释范围

这两组结果表明，被选中的配置在两种不同的请求长度或并发条件下仍有测得收益；它们不能证明普遍泛化，也不能证明 Agent 优于随机搜索。压测使用同一类合成 prompt，变更的是负载形状，不是任务语义分布。三个固定功能 prompt 只是冒烟测试。实验只有一台机器、一种模型、每组各三次重启测量；下一阶段应加入更多独立运行、其他模型和相同预算的多种搜索基线。
